# Database Schema

PostgreSQL 17 with PostGIS 3.5 (see [AI Development Notes](05-ai-development-notes.md#database-connections) for connection details). The PostGIS extension is available in the Docker image but is not enabled yet; it will be created in a migration when the first spatial table is added.

The planned donation schema is described in [Planned Features](06-planned-features.md#planned-schema). This document lists only the tables that currently exist.

## Current Tables

Laravel's default migrations were removed so that every migration in this project is generated with `php artisan make:migration` and carries the timestamp of when it was created (see [Migration Generation](05-ai-development-notes.md#migration-generation)). Framework tables are generated with their own Artisan commands (see [Framework Tables](#framework-tables)); the session and password reset tables come with accounts (milestone 9).

### users

Donors and administrators. Model: `App\Models\User`. Donors are created automatically from the email address entered on the donate page, with no password. The table holds donors' personal contact details; never copy its rows into the repository, issues, or chat.

| Column | Notes |
|--------|-------|
| name | Nullable |
| email | Unique, including among soft-deleted users, so a deleted account keeps its address reserved. Stored lowercase by the model, so finding a user by email is case-insensitive |
| email_verified_at | Nullable timestamp |
| password | Nullable; hashed by the model. Donors can always sign in with an email link once accounts are built |
| role | String, default `donor`: `donor` or `admin` (`User::ROLES`). Board members are given `admin` until they need different permissions. Not mass assignable, so form input can never change it |
| remember_token | Nullable |
| created_at, updated_at | |
| deleted_at | Nullable; soft deletes (see [Deletion](06-planned-features.md#deletion)) |

A user with **transaction history** cannot be deleted, soft or hard: `delete()` and `forceDelete()` throw a `LogicException`. `hasTransactionHistory()` is true when the user has any received donation (`succeeded`, `refunded`, or `partially_refunded`), including a soft-deleted one. Soft-deleting a user without it, such as a spam account from a carding attack, also soft-deletes their donations (all failed or pending), checkouts, and subscriptions, keeping them out of reports. Restoring the user does not restore those. Hard deletes are deliberate one-offs, which foreign keys refuse while any related row remains.

### designations

What a donor directed their donation toward (see [Designations](06-planned-features.md#designations)). Model: `App\Models\Designation`.

| Column | Notes |
|--------|-------|
| name | |
| slug | Unique, including among soft-deleted designations, so a slug always means the same fund. Travels in gateway metadata |
| description | Nullable |
| is_restricted | Boolean, default false. Donations to restricted designations can only be spent on them |
| is_active, sort_order | Boolean (default true) and integer (default 0), for the future donate-page selector |
| created_at, updated_at | |
| deleted_at | Nullable; soft deletes |

The **General Fund** (`general-fund`, unrestricted) is inserted by the table's migration rather than a seeder, because deploys run migrations but never seeders. `Designation::generalFund()` returns it. Checkouts, subscriptions, and donations created without a designation are assigned it automatically (`App\Models\Concerns\BelongsToDesignation`), including payments imported from outside our donation flow.

### gateway_customers

A user's customer records at a payment gateway. Model: `App\Models\GatewayCustomer`. A donor may have several, such as more than one Stripe customer for the same email address.

| Column | Notes |
|--------|-------|
| user_id | Foreign key; restricts deletes |
| gateway | String: `stripe` |
| gateway_customer_id | The gateway's customer ID. Unique together with `gateway`, including among soft-deleted rows |
| created_at, updated_at | |
| deleted_at | Nullable; soft deletes |

### checkouts

Every attempt to donate, recorded when the donor submits the donate form, including attempts that are never paid. Model: `App\Models\Checkout`.

| Column | Notes |
|--------|-------|
| reference | Unique UUID generated by the model; the public identifier sent to the gateway as metadata. The primary key stays an integer |
| user_id, designation_id | Foreign keys; restrict deletes. The designation defaults to the General Fund |
| amount_cents | Integer |
| currency | Lowercase ISO code as the gateway sends it, default `usd` |
| frequency | String: `one_time`, `monthly`, or `annual` (`Checkout::FREQUENCIES`) |
| status | String, default `started`: `started`, `completed`, or `expired` (`Checkout::STATUSES`). Indexed |
| gateway | String: `stripe` |
| gateway_session_id | Nullable until the gateway session is created. Unique together with `gateway` |
| expires_at, completed_at, reminder_sent_at | Nullable timestamps |
| created_at, updated_at | |
| deleted_at | Nullable; soft deletes |

### subscriptions

Recurring donations, synced from the payment gateway. Model: `App\Models\Subscription`.

| Column | Notes |
|--------|-------|
| user_id, designation_id | Foreign keys; restrict deletes. The designation defaults to the General Fund |
| gateway, gateway_subscription_id | Unique together, including among soft-deleted rows |
| amount_cents | Integer |
| currency | Lowercase ISO code as the gateway sends it, default `usd` |
| interval | String: `month` or `year` (`Subscription::INTERVALS`) |
| status | String: `incomplete`, `active`, `past_due`, `unpaid`, `paused`, or `canceled` (`Subscription::STATUSES`). Indexed |
| started_at, current_period_end, cancel_at, canceled_at | Nullable timestamps |
| gateway_data | Nullable JSONB copy of the latest gateway object |
| created_at, updated_at | |
| deleted_at | Nullable; soft deletes |

### donations

One row per payment, one-time or from a recurring donation, including failed payments. Model: `App\Models\Donation`.

| Column | Notes |
|--------|-------|
| user_id, designation_id | Foreign keys; restrict deletes. The designation defaults to the General Fund |
| subscription_id | Nullable foreign key; set for payments of a recurring donation |
| checkout_id | Nullable foreign key; set for payments started on our donate page |
| gateway, gateway_payment_id | Unique together, including among soft-deleted rows; the Stripe PaymentIntent. A payment received through several webhook events, a retried webhook, or a re-import is one row |
| gateway_invoice_id | Nullable; set for subscription payments. Indexed |
| amount_cents | Integer |
| fee_cents | Nullable integer; the gateway's processing fee, once known |
| refunded_cents | Integer, default 0 |
| currency | Lowercase ISO code as the gateway sends it, default `usd` |
| status | String: `pending`, `succeeded`, `failed`, `refunded`, or `partially_refunded` (`Donation::STATUSES`). Indexed |
| paid_at | Nullable timestamp |
| gateway_data | Nullable JSONB copy of the latest gateway object |
| created_at, updated_at | |
| deleted_at | Nullable; soft deletes |

A **received** payment is one we actually collected, even if it was refunded later: `succeeded`, `refunded`, or `partially_refunded` (`Donation::RECEIVED_STATUSES`, the `received()` scope, and `wasReceived()`). Received payments make up a user's transaction history.

### subscription_events

The history of each recurring donation in our own vocabulary, independent of the gateway. Model: `App\Models\SubscriptionEvent`. Append-only: there is no `deleted_at`, and the model throws a `LogicException` on any update or delete.

| Column | Notes |
|--------|-------|
| subscription_id | Foreign key; restricts deletes. `$subscription->events` lists them oldest first |
| type | String: `created`, `renewed`, `payment_failed`, `amount_changed`, `paused`, `resumed`, `canceled`, or `reactivated` (`SubscriptionEvent::TYPES`) |
| source | String: `webhook`, `import`, `admin`, or `donor` (`SubscriptionEvent::SOURCES`) |
| source_reference | The event, invoice, or action that caused it. Unique together with `subscription_id` and `type`, so sync code records events with `firstOrCreate()` on those three columns and a re-import never duplicates history |
| occurred_at | Timestamp |
| data | Nullable JSONB |
| created_at, updated_at | |

### webhook_events

Every incoming payment gateway webhook, stored before it is processed on the queue, for deduplication, debugging, and replay. Model: `App\Models\WebhookEvent`. Append-only: only the processing status changes after an event is stored, there is no `deleted_at`, and the model throws a `LogicException` on delete.

| Column | Notes |
|--------|-------|
| gateway, event_id | Unique together, so a redelivered event is stored once |
| type | The gateway's event type, such as `checkout.session.completed`. Indexed |
| payload | JSONB; the event as received |
| processed_at | Nullable timestamp; set once processing succeeds (`isProcessed()`) |
| attempts | Integer, default 0 |
| error | Nullable text; the last processing failure |
| created_at, updated_at | |

### donation_receipts

Tax receipts sent to donors. Model: `App\Models\DonationReceipt`. Issued and sent by `DonationReceipts` (see [Services & Commands](02-services-and-commands.md#donationreceipts-appservicesdonationreceiptsphp)).

| Column | Notes |
|--------|-------|
| user_id | Foreign key; restricts deletes |
| donation_id | Nullable foreign key; set for receipts for a single donation. At most one `single` receipt per donation, including soft-deleted receipts: a partial unique index (`donation_receipts_single_donation_unique`) makes the database refuse a second one |
| receipt_number | `WET-<tax year>-<random code>`, such as `WET-2026-K7Q2MX`. Random rather than sequential, so it reveals nothing about how many donations we receive. Unique, including among soft-deleted receipts, so a number is never reused |
| type | String: `single` or `annual_summary` (`DonationReceipt::TYPES`) |
| tax_year, amount_cents | Integers. The tax year is the year the donation was paid in Fort Collins time |
| sent_at | Nullable timestamp; set once the email is sent. A receipt issued but not sent, such as after an email failure, is sent on the next try |
| created_at, updated_at | |
| deleted_at | Nullable; soft deletes |

### Finding Records by Gateway ID

Models synced from a payment gateway use `App\Models\Concerns\HasGatewayId`. `findByGatewayId($gateway, $id)` looks a record up by the gateway's own ID, including soft-deleted rows, so receiving the same object again updates its record without restoring it and never creates a duplicate (see [Payment Sync and Import](06-planned-features.md#payment-sync-and-import)). Each model names its ID column in `GATEWAY_ID_COLUMN`: `gateway_customer_id` for gateway customers, `gateway_session_id` for checkouts, `gateway_subscription_id` for subscriptions, and `gateway_payment_id` for donations.

### leaf_applications

Requests to donate leaves to the leaf program, by drop-off or pickup. Model: `App\Models\LeafApplication`. The table holds donors' personal contact details, which are never shared; never copy its rows into the repository, issues, or chat.

| Column | Notes |
|--------|-------|
| type | String: `drop_off` or `pickup` (`LeafApplication::TYPES`) |
| name | |
| email | Stored lowercase by the model, so finding a donor's applications by email is case-insensitive |
| phone | |
| address | Up to 500 characters; where the leaves are coming from |
| estimated_bag_count | Integer; the donor's estimate, since many don't know the exact count in advance. Large counts may need a special pickup trip, while small ones are batched with other pickups |
| ready_now | Boolean; whether the bags are ready now |
| ready_date | Nullable date, set when the bags are not ready yet: when they will be, the soonest they can be picked up or dropped off. Donors never choose a pickup date or time; we schedule pickups around routes and volunteers |
| referral_source | Nullable text; how the donor heard about us |
| questions | Nullable text |
| terms_accepted_at | Timestamp; when the donor agreed to the program's terms |
| created_at, updated_at | |
| deleted_at | Nullable; soft deletes. Deleted applications are kept but hidden, including from `leaves:applications` (see [Deletion](06-planned-features.md#deletion)) |

## Framework Tables

Tables Laravel's own features use, generated unchanged from the framework's stubs. They hold no personal data of their own, though a queued job's payload can include the records it works on.

| Tables | Generated with | Used by |
|--------|----------------|---------|
| `cache`, `cache_locks` | `php artisan make:cache-table` | The `database` cache store: proof-of-work challenges already used, `queue:restart` signals, and later rate limits |
| `jobs` | `php artisan make:queue-table` | The `database` queue: jobs waiting for the queue worker |
| `failed_jobs` | `php artisan make:queue-failed-table` | Jobs that failed, kept for `queue:retry` (see [Operating a Server](07-deployment.md#operating-a-server)) |

## Framework Drivers

The drivers set in `laravel/.env.example`. A driver switches to `database` once its tables exist:

| Setting | Value | Notes |
|---------|-------|-------|
| `CACHE_STORE` | `database` | Uses the `cache` and `cache_locks` tables |
| `QUEUE_CONNECTION` | `database` | Uses the `jobs` and `failed_jobs` tables; the `queue` container runs the jobs |
| `SESSION_DRIVER` | `file` | Switches to `database` when accounts are built (milestone 9) |

Tests use in-memory stores instead (`array` for the cache and sessions, `sync` for the queue), set in `phpunit.xml`.
